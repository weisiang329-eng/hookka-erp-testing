The design source uses one `M()` helper for every module:

```js

```

Per dc13 module:

| Module | Items line | Metas (4 max) |
|---|---|---|
| Sales | `Aspen 3-Seater ×12, Hudson HB ×8` | Cust PO · Cust SO · Hub · Exp DD |
| Delivery | (same items pattern) | Cust PO · Cust SO · Hub · Exp Ship |
| Production | `Casa Furnishings KL · SO-2606-0142` | Our SO · Cust PO · Cust SO · Ref |

| Procurement | `Pine 2×2 ×400, MDF ×120` | ETA · Amount (only 2 metas) |

### Current state — what's wrong

`src/pages/m/components/DocCard.tsx` only supports `meta1 + meta2`. The
`RowVM` type in `src/pages/m/config/types.ts` carries those two only +
optional `subLine`. So:

- ❌ No place to put the items-summary line ("Aspen 3-Seater ×12, ...")
- ❌ No way to show 4 metas (Cust PO + Cust SO + Hub + Exp DD)
- ❌ Each module crammed different fields into the same 2-meta slot →
     looks inconsistent across screens

Plus `subLine` is being used inconsistently across modules — some put PO
there, some put state, some put items.

### Fix scope

1. **Extend `DocCard`** + `RowVM` to support an optional items line +
   array-of-N metas (rendered as a 2-column or 3-column chip grid
   underneath the title, before the trailing arrow).
2. **Rewrite `toVM` for every module** in `src/pages/m/config/modules.ts`
   to match dc13's `M()` shape:
   - sales, delivery → items line + 4 metas
   - production → items line + 4 metas
   - planning, procurement → items line + 2 metas
   - invoices, customers, suppliers, raw materials — match their dc13
     equivalents (each has its own card layout in the dc13 source)
3. **Match SubLine usage** across modules — make it ALWAYS the items
   summary, never the PO/state hack.

## ⚠️ Don't touch / regression risks

- **Drafts buffer** (per memory `arch_drafts_buffer_is_safety`) — the 2s
  debounce + retry + rollback + 20s polling exist BECAUSE cells silently
  lost data. Don't propose removing.
- **column-rename-map** (per memory `arch_column_rename_map_gotcha`) — any
  new camelCase SQL column needs an entry. Today's per-line attachment
  feature used existing files table — no risk.
- **Migration files alone are inert** (per memory `arch_per_line_discount`)
  — a new column reaches prod ONLY via runtime self-apply
  (`ALTER ADD COLUMN IF NOT EXISTS` awaited at top of POST/PUT). Today's
  /api/supplier-materials change used existing columns + JOIN — no risk.
- **MobileLayout overflowX:hidden** (commit `cc3b6a80`) — universal safety
  net for /m horizontal scroll. Don't remove. Internal `overflowX:auto`
  containers (SubTabs, StatusFlow) keep their own scrollbars and still
  work.
- **Desktop dc.html `data-dc-script`** (commit `cc3b6a80`) — script tag
  attributes are REQUIRED. Class MUST be `Component extends DCLogic`.
