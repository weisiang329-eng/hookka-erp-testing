You are implementing a full ERP system performance and stability refactor.
This task is NOT limited to Production/Delivery; it includes all major modules.

PROJECT GOAL
- Improve responsiveness, prevent freezes/hangs, and keep UI/data/behavior semantics unchanged.

NON-NEGOTIABLE CONSTRAINTS
1) UI parity: same columns, labels, wording, order, interaction behavior.
2) Data parity: do not remove required fields used by UI.
3) Behavior parity: search/filter/sort semantics must remain equivalent.
4) Progressive rendering may change mount timing only, never result membership.

MINIMUM MODULE SCOPE (FULL SYSTEM)
- Sales / CRM

- Delivery / Logistics
- Inventory / WIP / FG

Phase 3: Full-flow integration

Phase 4: Regression hardening
- run unit/integration/UI/visual tests

TECHNICAL REQUIREMENTS
A) Query/State/Render
- Query layer computes full-domain membership/order
- State layer holds canonical index + ordered ids
- Render layer controls viewport/window only
- chunking must never change result inclusion/exclusion

B) Progressive mount
- initial render window N0 = 200
- append batches ΔN = 300
- schedule with requestIdleCallback (fallback setTimeout(0))
- cancellation/versioning with queryVersion token

C) Unified scheduler
- single authority FSM: idle -> fetching -> cooldown -> idle
- one in-flight lock
- queryHash dedupe
- stale response suppression by sequence/version
- debounce visibility-driven refresh

D) Calendar stability
- pause non-critical refresh while date picker open/focused
- resume with debounce after commit/cancel
- prevent focus theft from global recompute

E) Sticky/frozen stability
- single scrollLeft authority between header/body
- explicit z-index ladder for body/sticky/header/popovers
- avoid transform on sticky ancestor chain
- deterministic shared width model for header/body

ANTI-REGRESSION RULES
- stable DOM structure for header/filter row
- stable row keys and deterministic identity
- no hidden comparator/null-ordering changes
- feature-flag rollout with immediate rollback path
