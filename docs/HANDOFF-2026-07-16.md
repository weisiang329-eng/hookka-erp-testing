## Task 1 — Impersonation ("login as user")  ⚠️ auth-sensitive

**Why:** we have RBAC, departments, a mobile portal and per-role route gates — and no way to
see the app as another user. Today, *"the sewing supervisor's Planning page is blank"* is not
reproducible without that person's password. Confirmed: no `impersonate` / `loginAs` / `actAs`
exists anywhere in the repo.

**Reference implementation:** the owner's other repo `weisiang329-eng/houzs-erp` has a careful
one — copy the REASONING, not its D1 SQL:
`functions/api/auth/impersonate.ts`, `stop-impersonate.ts`, `functions/_auth.ts` (the `imp`
JWT claim), `src/components/layout/impersonate-banner.tsx`.

### Security invariants (all five are load-bearing — do not drop any)
1. **Re-verify the original admin FROM THE DB, not from the token claim**, on every switch.
   A stale/forged claim must never grant admin.
2. **Short TTL** — 2h, vs the normal session length. An impersonated session must not linger.
3. **Do NOT update the target's `last_login`** — admin activity must never masquerade as the
   real user's.
4. **Audit as the ADMIN**, not the target: `impersonate_start` / `impersonate_stop` attributed
   to the real actor. Use `emitAudit` (`src/api/lib/audit.ts`).
5. **Collapse "user not found" and "user disabled" into ONE generic error**
   (`Invalid impersonation target`) so an admin can't probe which user ids exist.

### Our auth stack — what it must plug into (read ALL of these first)
- `src/api/lib/session-cookie.ts` — how a session token is minted/parsed.
- `src/api/lib/auth-middleware.ts` — resolves user + role per request. **Note the session
  CACHE**: `sessionCacheKey()`, `invalidateSessionCache()`, `purgeUserSessions()`. Impersonation
  must interact with this correctly or you'll serve a cached identity to the wrong session.
- `src/api/routes/auth.ts` (+ `auth-oauth.ts`, `auth-totp.ts`) — the existing login paths.
- `src/api/lib/rbac.ts` — `requireSuperAdmin(c)` gates the 7 user mutations; impersonation
  start must sit behind it.
- `src/api/lib/auth-wireup-notes.md` — read before touching any of the above.

### Suggested shape
- `POST /api/auth/impersonate {userId}` — `requireSuperAdmin`; re-verify admin from DB; mint a
  session for the target carrying the original admin id; 2h TTL; audit as admin.
- `POST /api/auth/stop-impersonate` — restore the admin's own session from the carried id
  (re-verified from the DB again).
- An amber top banner — "X impersonating Y" + **Return to admin** — so it is impossible to
  forget you're impersonating. Rendered in `src/layouts/DashboardLayout.tsx`.

### Why it wasn't done in-session
It has to be threaded through session minting + the middleware + the session cache. A rushed
version risks privilege escalation. It needs someone who has read the whole auth path.

## Shipped + verified this session (prod)

- **The big one: the schedule engine went from dying on every run to 5.1 s.** It had been
  killed mid-run since 15 Jul (five zombie `status='running'` rows) while the console showed
  PHASE 3 · FULL-AUTO and the queue grew to 1,715. Root cause was **~114 strictly serialized DB
  round-trips** (`CHUNK = 40`, three sequential queries per chunk), not the engine —
  `computeChain` runs in tens of ms. Fix: `CHUNK 40 → 500` (bind ceiling is 65535/11 ≈ 5,900
  rows, so 40 was 100× over-conservative).

  trip a CPU limit. When a Worker run hangs for minutes, suspect I/O round-trips, not CPU.**
