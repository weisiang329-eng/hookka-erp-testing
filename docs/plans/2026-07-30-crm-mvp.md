# CRM MVP — plan & status

Owner 2026-07-30, for outbound sales: turn the Customers module into a sales
pipeline. Everything recorded so a new hire can pick a customer up. Target:
**staging** (feature).

## Shipped in THIS PR (slice 1 — Customer 360 core)
- **Backend** `src/api/routes/customer-crm.ts` (mounted at `/api/customer-crm`):
  - `customer_contacts` — multiple named people per company (name, title,
    phone, email, role, is_primary). CRUD.
  - `customer_activities` — activity/follow-up timeline (type, summary, detail,
    contact, **next_follow_up**, outcome, created_by). Create/list/delete.
  - `GET /follow-ups` — upcoming + overdue follow-ups across customers (drives a
    "who to contact" list).
  - Tables runtime self-applied; every route RBAC-gated on `customers` +
    tenant-scoped by `org_id`.
- **UI** `src/components/customer/CrmPanel.tsx`, mounted on the customer detail
  view (`customers.tsx`): Contacts (add/list/delete) + Activity timeline
  (log call/meeting/quote/note with next-follow-up) — visible + usable.

## Remaining (next slices — NOT in this PR)
1. **Leads / pipeline stages** — a prospect layer (leads aren't yet real debtor
   accounts; the customers table requires a valid debtor code) + a stage board
   (lead → quoted → negotiating → won/lost) + lost-reason.
2. **One-click SEND** — wire the existing quotation/catalogue PDF generators
   into the in-app email engine (`sendMail`) + log "sent" to the timeline +
   read-tracking. (Building blocks already exist — see the CRM assessment.)
3. **Styles-liked wishlist** — extend `customer_products` with an interest flag.
4. **Onboarding / KYC** — collect consent letter + TIN + e-Invoice + SSM;
   `customers.ssmNo` exists, add `tin_number` / `einvoice_id` + a document
   upload (files.ts) + a "request documents" send flow.
5. **Dashboard surface** — "today's follow-ups" list (endpoint already exists)
   + a next-follow-up badge on the customer row.
6. **Contacts on the customer row/list** — surface primary contact.
